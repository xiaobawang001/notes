# 项目技术架构规则 (Notes App)

## 1. 项目概述
- 项目类型：个人笔记 Web 应用
- 核心功能：多用户注册/登录、笔记 CRUD（含树形目录）、全文搜索、角色权限（user/admin）
- 数据存储：Coze 多维表格（无传统数据库，通过 REST API 操作）
- 部署平台：Vercel (Monorepo 单仓库部署)

## 2. 仓库结构
- 根目录包含 `/frontend` 和 `/backend` 两个平行目录，其他目录如 docs 放在 backend 里
- 根目录必须包含 `vercel.json` 配置文件
- `vercel.json` 规则：`/api/v1/*` 请求转发至 backend，其余请求转发至 frontend

## 3. 前端技术栈 (Vue 3)
- 框架：Vue 3 + Vite 6 + TypeScript 5.7
- 状态管理：Pinia 2
- 路由：Vue Router 4 (配置路由守卫，未登录跳转 /login，非管理员访问 /admin 跳转首页)
- HTTP 请求：Axios 1.7 (请求拦截器自动注入 JWT Token，响应拦截器 401 跳转登录)
- UI 组件：Naive UI 2.40+ (`N` 前缀，用于表格/弹窗/表单/消息提示)
- 样式：UnoCSS 65+ (原子化 CSS，禁止大量自定义 CSS；自定义 shortcuts 和主题色通过 `uno.config.ts` 定义)
- 图标：Lucide-vue-next (按需导入，如 `<Home />`)
- Markdown 渲染：marked 14 + highlight.js 11（含代码块增强：行号、复制、折叠、行高亮）
- 图表：mermaid 11
- 代码风格：`<script setup lang="ts">`，禁止 Options API

## 4. 后端技术栈 (FastAPI)
- 框架：FastAPI 0.110+ + Python 3.10+
- HTTP 客户端：httpx 0.27+（用于调用 Coze REST API）
- 数据校验：Pydantic V2
- 数据存储：Coze 多维表格（通过 REST API 操作，无传统数据库）
- SQLAlchemy 2.0：仅用于表模型定义（`models/__init__.py`），作文档参考，不实际执行 ORM 操作
- 认证：JWT (python-jose) + 密码哈希 (passlib[bcrypt])
- 安全：敏感信息 (`COZE_TOKEN`, `SECRET_KEY`, `COZE_USERS_DATABASE_ID`, `COZE_NOTES_DATABASE_ID`) 必须从环境变量读取

## 5. 后端分层架构 (强制遵守)
- `api/v1/`：路由层，仅负责请求参数校验 (Pydantic) 和响应返回，禁止直接操作 Coze API
- `services/`：业务逻辑层，处理核心业务 (权限校验、数据转换、调用 repositories)
- `repositories/`：数据访问层，封装 Coze API 的 CRUD 操作（查询/插入/更新/删除）
- `models/`：SQLAlchemy ORM 表模型（仅作文档参考，不用于实际数据库操作）
- `schemas/`：Pydantic 请求/响应模型
- `core/`：全局配置 (`config.py`)、Coze API 客户端 (`coze_client.py`)、安全工具 (`security.py`)、依赖注入 (`deps.py`)
- `infrastructure/coze/`：Coze 基础设施（类型定义 `types.py`、过滤器构建 `filters.py`、数据映射 `mappers.py`）

## 6. 数据库设计规则（Coze 多维表格）

> Coze 字段类型仅支持：String、Integer、Time、Number、Boolean。
> Coze 不支持 UNIQUE、外键、复杂查询约束——所有约束在应用层强制。

### users 表（用户表）

| 字段名 | 类型 | 索引 | 说明 |
|--------|------|------|------|
| username | String | 否 | 用户名，应用层保证唯一 |
| password_hash | String | 否 | bcrypt 哈希后的密码 |
| email | String | 否 | 用户邮箱（可选） |
| created_at | Time | 否 | 注册时间，ISO 8601 |
| is_active | Integer | 是 | `1`=正常 / `0`=禁用 |
| role | String | 否 | `user`=普通用户 / `admin`=管理员 |

### notes 表（笔记表）

| 字段名 | 类型 | 索引 | 说明 |
|--------|------|------|------|
| user_id | Integer | 是 | 所属用户 ID |
| type | Integer | 是 | `1`=folder（目录）/ `2`=article（文章） |
| title | String | 否 | 标题 |
| slug | String | 否 | URL 标识（文章必填） |
| content | String | 否 | Markdown 正文 |
| parent_id | Integer | 是 | 父级记录 id，`0`=顶级根节点 |
| status | Integer | 是 | `1`=draft / `2`=published |
| pinned | Integer | 是 | 置顶：`0`=否 / `1`=是 |
| sort_order | Integer | 否 | 同级排序权重，越小越靠前 |
| word_count | Integer | 否 | 字数统计 |
| is_deleted | Integer | 是 | 软删除：`0`=正常 / `1`=已删除 |
| deleted_at | Time | 否 | 软删除时间戳 |
| created_at | Time | 否 | 创建时间 |
| updated_at | Time | 否 | 更新时间 |

> 所有字段值以**字符串**形式通过 Coze API 传输。

### 应用层约束
1. **username 唯一性**：注册时检查 users 表
2. **type 枚举**：只能是 `1`(folder) 或 `2`(article)
3. **status 枚举**：只能是 `1`(draft) 或 `2`(published)
4. **slug 唯一性**：同用户下文章 slug 唯一
5. **parent_id 合法性**：必须指向 `type=1` 且 `is_deleted=0` 的记录
6. **目录 status**：folder 创建/修改时 status 强制为 `published`
7. **软删除**：所有查询默认加 `is_deleted = 0`
8. **删除目录**：递归软删除所有子节点
9. **越权防护**：所有业务查询必须带 `user_id` 过滤
10. **管理员设定**：所有注册用户默认 `user`，管理员需在 Coze 表中手动将 `role` 字段改为 `"admin"`
11. **角色校验**：JWT payload 含 `role` 字段，后端 `require_admin` 依赖 + 前端路由守卫双重校验

## 7. API 接口规范
- 统一前缀：`/api/v1/`
- 统一响应格式：`{ "code": 0, "data": {...}, "msg": "success" }`
- 认证接口：
  - `POST /api/v1/auth/register` — 用户注册
  - `POST /api/v1/auth/login` — 用户登录
  - `POST /api/v1/auth/refresh` — 刷新 Token
- 笔记接口：
  - `GET /api/v1/notes` — 笔记列表（已登录=自己的，匿名=公开；支持 type/status/parent_id/search 过滤和分页）
  - `GET /api/v1/notes/categories` — 目录树（公开或按用户过滤）
  - `GET /api/v1/notes/search` — 全文搜索已发布文章（参数 `q`）
  - `GET /api/v1/notes/slug/{slug}` — 通过 slug 获取文章详情（公开）
  - `GET /api/v1/notes/{id}` — 通过 ID 获取笔记详情
  - `POST /api/v1/notes` — 创建笔记（需登录）
  - `PUT /api/v1/notes/{id}` — 更新笔记（需登录，仅限自己的）
  - `DELETE /api/v1/notes/{id}` — 删除笔记（需登录，仅限自己的）
- 健康检查：`GET /api/v1/health`
